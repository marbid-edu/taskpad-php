Objectives 
• Build a small server-side PHP web application that processes HTML forms and 
returns dynamic pages. 
• Use PHP superglobals ($_GET, $_POST, $_SERVER) safely to handle inputs and 
HTTP flow.  
• Create UML diagrams (at minimum: Use Case + Class; Activity optional) as part of 
the analysis model. 
• Demonstrate simple input validation/sanitization and basic HTTP responses 
(including redirects and proper content types).  


Overview 
Build “TaskPad PHP”, a minimal task tracker where users can: 
• Add a task (title required; optional description; priority: Low/Med/High; due date 
optional). 
• List tasks with simple filtering (by text and/or priority). 
• Mark a task complete and delete tasks. 
• Persist tasks in a flat JSON file on the server (no DB) to keep scope light for first
PHP. 


The app should: 
• Serve an HTML form that posts to a PHP endpoint. 
• Validate required fields server-side; echo friendly errors and re-render the form 
with the user’s entries. 
• On success, store the task and redirect to the list view to avoid double-submits 
(PRG pattern).  
• Provide a list view with filtering via query string (?q=search&priority=High) and 
show counts. 
• Allow “Complete”/“Delete” actions via POST 

Requirements 
Technology & Setup 
• Plain PHP 7.4+ or 8.x
• No frameworks; no DB. Persist tasks in /data/tasks.json (server-side JSON file). 
• Keep server-side concerns (validation, sanitization, redirects, content type) in PHP.  
• Use semantic HTML/CSS for a clean, responsive layout (consistent with Project 1/2 
expectations). 


Features 
1. Create Task (POST) 
o Fields: title (required), description (optional), priority (Low/Medium/High), due 
(YYYY-MM-DD optional). 
o Server-side validation: title non-empty; due date format if provided. 
o On validation error: re-render form; preserve inputs; show inline messages. 
o On success: append to JSON store; redirect to list view (PRG).  


2. List & Filter Tasks (GET) 
o Display all tasks with badges for priority and state (Open/Completed). 
o Filters: text query q matches title or description (case-insensitive), and priority 
filter. 
o Show empty and “no matches” states. 


3. Complete/Delete (POST) 
o Buttons in the list perform actions
o After action, redirect back to the list with a flash message. 


4. Data Model (minimum) 
{ 
"id": "string-uuid-or-timestamp", 
"title": "string", 
"description": "string", 
"priority": "Low|Medium|High", 
"due": "YYYY-MM-DD|null", 
"completed": false 
} 


Server-Side Input Handling & Security 
• Use $_POST/$_GET to read inputs.  
• Sanitize/validate before using or storing (e.g., trim, length checks, whitelist for priority, 
simple date regex). 
• If you generate links with query strings, ensure you safely consume them.  
• If you ever echo user data back into HTML, escape appropriately to avoid XSS. 
• For any non-idempotent operation, use POST (not GET). 
• Use header('Location: ...') for redirects and set appropriate Content-Type where 
needed (e.g., JSON test output).
